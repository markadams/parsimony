Parsimony on Grid

How a bit-width decision travels from a Python search into a Grid kernel on an A100, and what came back. Every code panel below is the real file, not a sketch.

The loop

Parsimony splits into two halves that never need to know about each other. A search proposes a precision configuration; an evaluator runs the program under it and scores the result. Grid is the evaluator here, and the seam between them is a command-line flag and a JSON record — which is why no probe costs a rebuild.

What "storage rounding" does

A variable is stored at k significand bits with float64's exponent range, then read back and computed on in full fp64. Nothing else changes. This is the exact function round_bits.h applies on the GPU and parsimony.formats.round_to applies in Python — the two agree bitwise over 372 doubles, ties and subnormals included.

The highlighted bits are kept; the struck-through ones are discarded and the value is rounded to nearest, ties to even.

What came back

Grid's coarse Dirac stencil, rounded in storage, then CG against the rounded operator with the answer judged against an exact second copy of it. Twelve formats, two right-hand-side cases, four A100s.

Show the numbers

fp16 is absent from both charts on purpose. It gave δ = 1.000 exactly — every stencil entry underflowed its 5-bit exponent and the operator rounded to zero. That is a failure of exponent range, not of significand bits, so plotting it against a significand-bit axis would misattribute it. bf16, with three fewer significand bits but fp32's exponent range, behaved exactly like the 8-bit virtual format.

Preliminary, and not physics. Free field (unit gauge), random subspace, nbasis 20, Ls 8, 16³×32, CG tolerance 10−8. The gauge configuration for the real study has not arrived, so this exercises the machinery rather than an ensemble. Every JSON record carries all of those fields so a cheap run cannot later be read as a physics one. Two independent right-hand-side cases agree to three digits.
